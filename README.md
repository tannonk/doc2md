# doc2md

PDF/MS Office to markdown conversion.

This tool can be used to convert PDF and MS Office documents into markdown format using vision-language models (VLMs), with optional image extraction and captioning. 

The conversion pipeline is designed and tested with [`LightOnOCR-2-1B-bbox-soup`](https://huggingface.co/lightonai/LightOnOCR-2-1B-bbox-soup) for OCR and [`nemotron-3-omni`](https://huggingface.co/nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-FP8) for image captioning. Steps 2 and 3 (image resolution and captioning) are heavily dependent on the output format generated by LightOnOCR-2-1B-bbox-soup. For documents *without* images, you can swap out the bbox-soup model for the text-only variant [`LightOnOCR-2-1B`](https://huggingface.co/lightonai/LightOnOCR-2-1B), which is reported to provide more accurate text extraction and skip steps 2 and 3.

**Why LightOnOCR-2-1B-bbox-soup for OCR?** 

`lighton/LightOnOCR-2-1B-bbox-soup` embeds image placeholders like:

    ![image](image_1.png)670,83,932,167

Where the trailing numbers are the bounding box coordinates of the image in the original page. This allows for accurate cropping of images from the original page images (applied in step 2), which can then be captioned and embedded in the markdown (step 3).

In our tests, this model produced the best results for complex documents with tables, figures, and multi-column layouts. See the [paper](https://arxiv.org/pdf/2601.14251) for more details on the model and its training.


## Setup

```bash
conda env create -f environment.yml   # python 3.12 + poppler + this package (editable, with dev tools)
conda activate doc2md
bash scripts/setup_libreoffice.sh     # only needed for --conversion-method vlm on Office files and soffice not already installed
cp .env.example .env                  # add HF_TOKEN, used by docker/*/serve.sh for gated models
pytest -m "not vllm"                  # offline tests
```


## Pipeline

### Step 1: PDF → markdown

Launch a vLLM server with an OCR-specific VLM:

```bash
bash docker/light-on-ocr2/serve.sh # Default model used: `LightOnOCR-2-1B-bbox-soup`
```

In a new terminal, run the conversion script on a directory of PDFs:

```bash
python -m doc2md.convert \
    -i data/local/raw_data/pdf_docs \
    -o data/local/md/
```

**NOTE:** `LightOnOCR-2-1B-bbox-soup` outputs markdown files with bounding box placeholders for images. If you don't need image processing, you can use the text-only model `LightOnOCR-2-1B` for better performance, e.g.

```bash
MODEL="lightonai/LightOnOCR-2-1B" bash docker/light-on-ocr2/serve.sh
```

```bash
python -m doc2md.convert \
    -i data/local/raw_data/pdf_docs \
    -m lightonai/LightOnOCR-2-1B \
    -o data/local/md/
```

#### Conversion methods

`--conversion-method` chooses how each file is turned into Markdown. There are two primary backends:

- **VLM**: renders every page to an image and OCRs it with the vLLM server (requires external tools, see below).
- **anydoc**: reads text straight from the source file.

We strongly recommend using `vlm` (default). This is slower than `auto`/`native`, but it works well on all file types and produces a universal output format with high-quality output.

| method | PDF | TIFF | Office / OpenDocument |
|---|---|---|---|
| `vlm` (default) | VLM | VLM | LibreOffice → PDF → VLM |
| `auto` | VLM | VLM | anydoc |
| `native` | anydoc (text layer only) | fails: anydoc can't read TIFF | anydoc |

Supported file types for Office / OpenDocument include `.doc`, `.docx`, `.docm`, `.dotx`, `.dotm`, `.odt`, `.rtf`, `.xls`, `.xlsx`, `.xlsm`, `.xltx`, `.ods`, `.ppt`, `.pptx`, `.pptm`, `.ppsx`, `.potx`, `.odp`.

External tools are needed only for files that go to the VLM:

- **vLLM server**: checked at startup, and skipped when no file in the batch goes to the VLM.
- **poppler**: for PDFs.
- **LibreOffice**: only for Office files under `vlm`. A `native` batch, or a batch of Office files under `auto`, needs none of these.

**Scanned PDFs under `native`:** anydoc can't OCR, and doc2md never sends documents to FireCrawl's hosted OCR. A scanned or image-only PDF therefore fails with a message listing the pages that need OCR. Convert it with `--conversion-method auto` or `vlm` instead. TIFFs under `native` fail the same way, and a warning at startup lists them.

**Failures and reruns:**

- A file that can't be converted at all writes **no** `.md` and counts as `failed`. Examples: a render error, OCR failing on every page, or an anydoc error. The next run retries it automatically.
- If only some pages fail OCR, the file is still written. Those pages get `<!-- OCR FAILED: ... -->` placeholders, the front matter lists them in `ocr_failed_pages: [..]`, and the file counts as `partial`. Use `--force` to retry it.

**Front matter:** every output file starts with these fields:

- `file_hash`, `raw_file_path`, `conversion_date` and `conversion_method` (the method actually used for that file).
- `extractor`: what produced the Markdown. For VLM output it's the model id (e.g. `"lightonai/LightOnOCR-2-1B"`); for native output it's anydoc and its version (e.g. `"anydoc v0.2.4"`).
- `ocr_failed_pages`: only on VLM output where some pages failed.


### Step 2: Bounding box image resolution

LightOnOCR-2-1B-bbox-soup outputs bounding box placeholders for images, but does not include the actual image data. This stage resolves those placeholders by extracting the corresponding images from the original PDF page images and saving them as separate files.

```bash
# run resolution on the output of stage 1
python -m doc2md.resolve \
    -i data/local/md/data_safety_sheets
```

Output files will be saved to `data/local/md/data_safety_sheets/resolved/` and the corresponding cropped images will be saved as PNG files under `resolved/images/`



### Step 3: Image captioning

Image captioning is performed using a pre-trained vision-language model. The model generates captions for the images extracted in step 2 and inserts them as alt text in image markdown tags in the corresponding markdown files.

Launch a vLLM server with an image captioning model:

```bash
bash docker/nemotron-3-omni/serve.sh
```

Run image captioning on the output of step 2

```bash
python -m doc2md.caption \
    -i data/local/md/data_safety_sheets/resolved
```

`--model` takes a bare Hugging Face-style name (e.g. `nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-FP8`, the default); it's checked against `--base-url` and routed to the local vLLM server automatically. Any other LiteLLM provider string (e.g. `anthropic/claude-3-5-sonnet`) should work too.


## Hardware requirements

This tool has been developed and tested on a NVIDIA DGX Spark with a single GB10 GPU. Docker containers are provided for serving the VLMs with `vLLM`. All VLM calls assume an OpenAI-compatible API endpoint, so alternative endpoints can be used if needed. For example, to run the text extraction step with a model served with `ollama`, simply set `--base-url http://localhost:11434/v1` and `--model ollama_model_name` to point to your local Ollama server, e.g.

```bash
python -m doc2md.convert \
    -i data/examples/raw \
    -o data/examples/md-ollama \
    --base-url http://localhost:11434 \
    --model maternion/LightOnOCR-2 \
    --conversion-method vlm
```

**NOTE:** if using a quantized model through `ollama`, extraction quality may be lower than the original model.
